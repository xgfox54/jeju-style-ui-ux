# 제주 디자인 시스템 적용 체크리스트

서비스에 제주 디자인 시스템을 적용할 때 개발·디자인·검수자가 함께 확인하는 최소 체크리스트다.

## 1. 시작 전

- [ ] 화면 성격을 `work` 또는 `public`으로 먼저 결정했다.
- [ ] `design/jeju-tokens.css`를 값의 단일 원천으로 사용한다.
- [ ] 공통 CSS 로드 순서가 `tokens → components → public(필요 시) → service` 순서다.
- [ ] 대민 화면에는 `data-jeju-profile="public"`을 지정했다.
- [ ] 외부 폰트 CDN을 필수 의존성으로 사용하지 않는다.

## 2. 브랜드

- [ ] Blue `#0173BC`, Green `#00A074`, Orange `#F18101` 원색을 서비스 코드에 반복 하드코딩하지 않는다.
- [ ] Primary 구조색은 Blue를 기본으로 한다.
- [ ] Green/Orange는 역할 기반 보조색으로 사용한다.
- [ ] Green/Orange 채움 위 흰 글자가 필요하면 접근성용 strong/dark 역할 토큰을 사용한다.
- [ ] 상태를 색 하나만으로 표현하지 않는다.

## 3. 업무 UI

- [ ] 첫 화면의 정보 구조가 제목/주요 액션 → KPI 또는 검색 → 표/업무목록 순으로 명확하다.
- [ ] 숫자 열은 오른쪽 정렬하고 날짜 형식을 통일했다.
- [ ] 긴 표는 `.jeju-table-wrap` 내부에서만 가로 스크롤된다.
- [ ] 주요 처리 버튼과 단순 조회 버튼의 위계가 구분된다.
- [ ] 오류·빈 상태·로딩 상태를 정의했다.

## 4. 대민 UI

- [ ] 기본 컨트롤 높이 48px 프로필을 사용한다.
- [ ] H1은 페이지 목적을 일반 사용자가 바로 이해할 수 있는 문장으로 작성한다.
- [ ] 전문 행정용어를 필요한 수준으로 풀어 쓴다.
- [ ] 모바일 390px에서 body 가로 스크롤이 발생하지 않는다.
- [ ] 터치 가능한 요소 간 간격과 크기가 충분하다.

## 5. 접근성

- [ ] 모든 입력 요소에 명시적 label이 있다.
- [ ] placeholder를 유일한 label로 사용하지 않는다.
- [ ] 키보드만으로 주요 기능을 사용할 수 있다.
- [ ] `:focus-visible` 포커스 표시가 보인다.
- [ ] 일반 텍스트 명도 대비 4.5:1을 목표로 검토했다.
- [ ] 오류 메시지는 색뿐 아니라 텍스트로 원인을 알려준다.
- [ ] 모달·탭 등 동적 UI에 적절한 ARIA 속성이 있다.
- [ ] `prefers-reduced-motion`, Windows 고대비 환경에서 기능이 유지된다.

## 6. AI/Codex 작업

- [ ] 작업 전 `DESIGN.md`와 `skills/jeju-design/SKILL.md`를 읽게 했다.
- [ ] AI가 임의 HEX, 임의 spacing, 외부 CDN을 추가하지 않았는지 확인했다.
- [ ] 신규 공통 패턴은 서비스 내부 복제보다 디자인 시스템 확장을 먼저 검토했다.

## 8. v0.2 컴포넌트 점검

- [ ] 아코디언 제목이 heading 안의 버튼이고 `aria-expanded`/`aria-controls`가 패널과 연결된다.
- [ ] 툴팁에만 존재하는 필수 정보가 없다. 툴팁은 포커스로도 열리고 Esc로 닫힌다.
- [ ] 드롭다운 메뉴가 키보드만으로 열기·이동·닫기·포커스 복귀까지 동작한다.
- [ ] 체크박스·라디오 묶음에 `fieldset`과 `legend`가 있다.
- [ ] 스위치의 켜짐/꺼짐이 색 외에 문구로도 보인다.
- [ ] 필터 칩에 `aria-pressed`가 있고 제거 버튼에 대상이 드러나는 이름이 있다.
- [ ] 표 정렬이 `aria-sort`와 아이콘 모양을 함께 바꾼다.
- [ ] 표 전체 선택이 부분 선택 시 indeterminate 상태를 표시한다.
- [ ] 560px 이하에서 표가 `.jeju-table--stack`으로 접히고 `data-label`이 채워져 있다.
- [ ] 파일 업로드에 선택한 파일 목록과 파일별 삭제가 있다.
- [ ] 진행률에 `role="progressbar"`와 숫자 텍스트가 함께 있다.
- [ ] 단계 표시가 완료·현재 단계·예정을 문구로 알린다.
- [ ] 폼에 기본/hover/focus/readonly/disabled/필수/오류/성공 상태가 정의되어 있다.
- [ ] 제출 실패 시 오류 요약이 각 입력으로 이동시킨다.

## 7. 자동 검사

React 프로젝트(Tier 2)는 아래 9절도 함께 점검한다.

개발 중:

```bash
python design/check_design.py --report <서비스경로>
```

CI/배포 전:

```bash
python design/check_design.py --gate <서비스경로>
```

정본 변경 후:

```bash
python design/check_design.py --canon
```

자동 검사는 보조 수단이다. 실제 키보드 조작, 스크린리더 의미 구조, 모바일 화면, 고대비 모드는 별도 수동 검수한다.

## 9. React 레지스트리(Tier 2) 점검

- [ ] `components.json`의 `registries`에 `@jeju`가 있고, 컴포넌트를 `@jeju/...`로 설치했다. shadcn 기본 레지스트리의 같은 이름 항목을 섞지 않았다.
- [ ] 전역 CSS가 `@import "../styles/jeju-tokens.css" layer(base);`로 토큰을 불러온다.
- [ ] `styles/jeju-tokens.css`를 직접 고치지 않았다(정본과 같다, S6).
- [ ] 프리셋의 `.dark` 팔레트, Geist 글꼴 import, 다크 모드 ThemeProvider를 지웠다.
- [ ] 대민 화면은 `<html data-jeju-profile="public">`이고 업무 화면은 속성이 없다.
- [ ] 아이콘은 `@/components/ui/jeju-icons`만 쓴다.
- [ ] 색은 테마 변수나 `var(--jeju-*)`로만 썼고 `bg-blue-500`, `bg-[#...]`가 없다(S1).
- [ ] 스위치 옆에 켜짐/꺼짐 문구, 상태 배지에 문구가 있다.
- [ ] `python <저장소>/design/check_design.py --gate <프로젝트 루트>`가 통과한다.

## 10. 대민 터치 영역 · 대민 서비스 컴포넌트 점검

- [ ] 대민 화면의 버튼 · 링크 · 칩 · 선택 행이 실제로 누를 수 있는 영역 44×44px 이상이다(`--jeju-target-min`). 업무 화면은 24px 이상이거나 간격 예외를 만족한다.
- [ ] 대민 화면에 13px보다 작은 글자가 없다. 오류 문장은 `--jeju-feedback-font`를 쓴다.
- [ ] 서비스 검색에 보이는 라벨이 있고, 결과 수가 문구로 바뀌며, 결과가 없을 때 다음 행동(초기화 · 상담)을 안내한다.
- [ ] 자격 확인 결과가 자가 확인이며 최종 판단이 아니라는 안내가 있다. 결과를 색만이 아니라 문구로 알린다.
- [ ] 서식 내려받기 버튼 이름에 문서명과 형식·크기가 들어 있다.
- [ ] 문의 안내의 전화번호는 `tel:` 링크이고, 지도는 끼워 넣지 않고 링크로 연결한다. 새 창 링크는 새 창임을 알린다.

## 11. 망분리 전달(standalone)

- [ ] 기관에 보내는 화면 시안은 `python tools/build_standalone.py 화면.html --out 폴더`로 만든 단일 HTML이다.
- [ ] 생성 시 WARN(남은 로컬 참조)이 없고, 네트워크 없이 열어도 아이콘 · 스타일 · 동작이 그대로다.

## 12. 로딩·오류 상태 · 상세 패널 · 글꼴

- [ ] 데이터를 받아 오는 목록 · 상세에 불러오는 중 · 오류 · 결과 없음 상태가 모두 있다. 오류 문구가 무엇이 안 됐는지와 다음 행동(다시 시도 · 문의)을 알려 준다.
- [ ] 불러오는 동안 영역에 `aria-busy`가 켜지고, 상태가 바뀌면 문구로 알린다(`data-jeju-async-live` 또는 React `role="status"`).
- [ ] 키보드로 다시 시도를 눌러도 포커스가 문서 처음으로 튕기지 않는다.
- [ ] 상세 패널을 여는 버튼 이름에 대상이 드러나고, Esc로 닫으면 그 버튼으로 포커스가 돌아온다. 390px에서 패널이 화면 폭 전체를 쓴다.
- [ ] 서버에서 한 페이지씩 받는 React 표는 `DataTable manual`과 `totalCount`를 쓰고, 정렬을 바꾸면 1페이지로 돌아간다.
- [ ] 글꼴은 `jeju-fonts.css`로 자체 호스팅하고 외부 글꼴 CDN이 없다. 글꼴 파일을 아직 두지 않았다면 S8 WARN이 나오는 이유를 알고 있다.

## 13. 서버 조회형 목록 · 인쇄

- [ ] 서버가 그리는 목록은 조회 조건 · 정렬 · 페이지 · 페이지 크기가 주소에 남는다. 주소를 복사해 다시 열면 같은 화면이 나온다.
- [ ] 정렬 링크가 `th[aria-sort]` 안에 있고, 숨김 글자로 동작을 알리며, 아이콘 모양이 정렬 상태를 따라 바뀐다.
- [ ] 쪽 번호 링크 이름이 "2페이지"처럼 읽히고 현재 쪽에 `aria-current="page"`가 있다. 없는 이전 · 다음은 비활성으로 보인다.
- [ ] 선택 상자를 고르기만 해도 페이지가 바뀌지 않는다("적용" · "검색" 버튼으로 제출).
- [ ] 정렬 · 쪽을 바꾼 뒤 Tab을 누르면 목록 안에서 시작한다(주소 끝 목록 제목 앵커).
- [ ] 인쇄 미리보기에서 메뉴 · 버튼 · 검색 폼 · 페이지 이동 · 선택 상자가 빠지고, 기관 · 조회 조건 · 출력 일시가 남는다. 표가 잘리지 않고 끝까지 나온다.
- [ ] 상세 패널을 연 채 인쇄하면 패널 내용만 나온다.
- [ ] 토큰 값을 바꿨다면 `python tools/build_token_docs.py`로 `docs/tokens.md`를 다시 만들었다(J19).
