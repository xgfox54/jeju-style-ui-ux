# 제주 디자인 시스템 접근성 기준

제주 디자인 시스템은 KWCAG/WCAG AA를 기본 목표로 한다. 이 문서는 특히 제주 브랜드 3색을 UI에 적용할 때의 텍스트 대비와 상호작용 원칙을 고정한다.

## 1. 브랜드 원색과 텍스트 대비

| 배경 | 흰색 글자 대비 | 짙은 글자(`--jeju-text-strong`) 대비 | 기본 사용 |
|---|---:|---:|---|
| Blue `#0173BC` | 약 5.02:1 | 약 3.45:1 | **흰색 글자** |
| Green `#00A074` | 약 3.34:1 | 약 5.18:1 | **짙은 글자** 또는 장식 배경 |
| Orange `#F18101` | 약 2.66:1 | 약 6.50:1 | **짙은 글자** 또는 장식 배경 |

일반 크기 텍스트의 목표 대비는 4.5:1이다.

따라서:

- Blue 원색 버튼은 흰색 글자를 사용할 수 있다.
- Green/Orange **원색** 위에 일반 크기의 흰색 글자를 사용하지 않는다.
- Green/Orange 원색을 반드시 채움 배경으로 써야 하면 짙은 글자를 사용한다.
- 흰색 글자가 필요한 Green/Orange 채움 버튼에는 `--jeju-green-dark`, `--jeju-orange-dark` 또는 semantic strong alias를 사용한다.

## 2. 접근성용 파생 역할색

다음 파생색은 제주 원색을 대체하는 새로운 CI 원색이 아니라 UI 가독성을 위한 역할색이다.

| 역할 | 토큰 | 흰색 대비 |
|---|---|---:|
| Green strong | `--jeju-green-dark` | 약 4.52:1 |
| Orange strong | `--jeju-orange-dark` | 약 4.52:1 |
| Danger | `--jeju-danger` | 약 5.48:1 |
| Warning | `--jeju-warning` | 약 5.42:1 |

버튼에는 의미 alias인 `--jeju-secondary-strong`, `--jeju-accent-strong`을 우선 사용한다.

## 3. 상태 표현

색은 보조 정보다.

잘못된 예:

- 초록색 점만으로 완료 표현
- 빨간 테두리만으로 입력 오류 표현
- 주황색 행만으로 검토 필요 표현

권장 예:

- `완료` 텍스트 + success badge
- 오류 테두리 + 구체적인 오류 문장
- `검토 필요` badge + 필요한 조치 문장

## 4. 키보드

- 모든 주요 기능은 Tab/Shift+Tab으로 접근할 수 있어야 한다.
- Tab, modal, drawer 등의 조작에 마우스만 필요한 기능을 만들지 않는다.
- `:focus-visible`을 제거하지 않는다.
- 포커스가 배경과 구분되지 않으면 `--jeju-focus-ring`을 사용한다.
- 모달은 가능하면 native `<dialog>`를 사용한다.

## 5. 폼

- 모든 input/select/textarea에 연결된 label을 둔다.
- placeholder를 label 대신 사용하지 않는다.
- 필수 입력은 색 또는 별표만이 아니라 텍스트나 접근성 이름으로도 전달한다.
- 오류는 무엇이 잘못됐고 어떻게 수정해야 하는지 알려준다.

## 6. 동작·사용자 환경

공통 스타일은 다음 환경 설정을 존중한다.

- `forced-colors: active`
- `prefers-contrast: more`
- `prefers-reduced-motion: reduce`

애니메이션은 기능 이해에 필수적이지 않아야 한다.

## 7. 대민 서비스 추가 기준

대민 프로필은 업무 프로필보다 더 큰 터치 영역과 본문 크기를 사용한다.

- 기본 컨트롤: 48px
- 기본 본문: 17px
- 모바일 기준 검수: 390px
- 중요한 안내를 hover에만 숨기지 않는다.
- 링크 문구는 “여기”, “자세히”보다 이동 목적을 설명한다.

## 8. 수동 검수

자동 검사만으로 접근성 적합성을 보장할 수 없다. 배포 전 최소한 다음을 직접 확인한다.

1. 키보드만으로 화면 처음부터 끝까지 이동
2. 포커스 표시 확인
3. 200% 확대
4. 390px 모바일 폭
5. Windows 고대비
6. 오류/빈 상태/로딩 상태
7. 실제 스크린리더 의미 구조가 필요한 핵심 서비스의 별도 점검
8. 인쇄 미리보기: 조작 요소가 빠지고 조회 조건 · 출력 일시가 남는지, 상태를 문구로 읽을 수 있는지

## 9. 컴포넌트 키보드·ARIA 규약

공통 컴포넌트는 다음 조작 규약을 지킨다. 서비스에서 같은 패턴을 다시 만들지 말고 이 규약을 따르는 공통 컴포넌트를 재사용한다.

| 컴포넌트 | 키보드 | 필수 ARIA |
|---|---|---|
| 아코디언 | Tab으로 제목 버튼 이동, Enter/Space로 열고 닫기, 위/아래/Home/End로 제목 간 이동 | 제목은 heading 안의 button, `aria-expanded`, `aria-controls`, 패널 `role="region"` + `aria-labelledby` |
| 툴팁 | 트리거 포커스 시 표시, Esc로 닫기, 포인터를 말풍선 위로 옮겨도 유지 | 트리거 `aria-describedby`, 말풍선 `role="tooltip"` |
| 드롭다운 메뉴 | 아래/위 화살표로 열기, 화살표·Home·End로 항목 이동, Esc로 닫고 트리거로 포커스 복귀, Tab으로 이탈 시 닫힘 | 트리거 `aria-haspopup="menu"` + `aria-expanded`, 목록 `role="menu"`, 항목 `role="menuitem"` |
| 체크박스·라디오 | 네이티브 동작 유지(Space, 라디오 그룹 화살표) | 묶음은 `fieldset` + `legend`, 시각적 라벨이 없으면 `.jeju-visually-hidden` 라벨 |
| 스위치 | Space로 전환 | 켜짐/꺼짐을 `.jeju-switch__state` 문구로도 제공 |
| 칩 | 필터 칩은 Space/Enter로 토글, 제거 버튼은 Tab으로 도달 | 필터 칩 `aria-pressed`, 제거 버튼에 대상이 드러나는 `aria-label` |
| 표 정렬 | 열 제목 버튼을 Enter/Space로 전환 | `th[aria-sort]`를 none/ascending/descending으로 갱신하고 아이콘 모양도 함께 변경 |
| 표 선택 | 헤더 체크박스로 전체 선택, 부분 선택은 indeterminate | 각 행 체크박스에 행을 식별하는 접근성 이름 |
| 파일 업로드 | 파일 입력이 포커스 가능한 상태로 남고 라벨 버튼에 포커스 링 표시 | 파일별 삭제 버튼에 파일명을 포함한 `aria-label` |
| 진행률 | 조작 없음 | `role="progressbar"` + `aria-valuemin/max/now`, 숫자 텍스트 병기 |
| 단계·마법사 | 이전/다음 버튼으로 이동하고 양 끝에서 비활성 | 현재 단계 `aria-current="step"`, 완료·현재·예정을 문구로 제공 |
| 드로어(모바일 메뉴) | 토글 버튼으로 열고 Esc로 닫으며 토글로 포커스 복귀 | 토글 `aria-expanded` + `aria-controls` |
| 모달·확인 대화상자 | 네이티브 dialog 모달 동작, Esc로 닫기 | 제목과 연결된 `aria-labelledby` 또는 `aria-label` |
| 서비스 검색 | 검색어 입력과 분류 칩(Space/Enter)으로 즉시 거름, 결과가 없을 때 초기화 버튼이 검색창으로 포커스를 돌려줌 | 보이는 라벨이 있는 `type="search"`, `form[role=search]`, 분류 칩 `aria-pressed`(한 번에 하나), 결과 수 `role="status"` |
| 신청 자격 확인 | 질문마다 라디오 그룹 화살표 이동 | 질문은 `fieldset` + `legend`, 보충 설명은 `aria-describedby`, 결과는 `role="status"` 문구 + 알림 색 |
| 서식 내려받기 | 링크를 Tab으로 이동 | 링크 이름에 문서명 · 형식 · 크기와 보이는 글자 "내려받기"를 함께 둔다(WCAG 2.5.3) |
| 문의·방문 안내 | 전화 링크 · 지도 링크를 Tab으로 이동 | 항목은 `dl`, 새 창 링크는 "(새 창)"을 숨김 글자로 알림 |
| 로딩·오류 상태 | 다시 시도 버튼을 Tab으로 이동해 Enter/Space. 버튼이 상태 전환으로 사라지면 포커스는 상태 영역(React 표는 건수 문구)으로 옮겨 간다 | 불러오는 동안 영역 `aria-busy="true"`, 바뀐 상태는 숨김 live 영역(`data-jeju-async-live`, React는 `role="status"`)으로 알림, 오류는 아이콘 + 문구(React `role="alert"`), 스켈레톤은 `aria-hidden` |
| 상세 보기 사이드 패널 | 표 안 여는 버튼을 Enter/Space로 열기, Tab이 패널 안에 머묾, Esc로 닫으면 연 버튼으로 포커스 복귀 | 네이티브 `dialog` 모달 + 제목과 연결된 `aria-labelledby`, 여는 버튼 이름에 대상("IC-2609128 상세 보기"), 상세 내용은 `dl` |
| 서버 조회형 표 | 정렬 · 페이지 이동 · 페이지 크기는 일반 표와 같다. 불러오는 동안에도 머리글 버튼과 페이지 링크가 그대로 남아 포커스를 잃지 않는다 | 표 `aria-busy`, "목록을 불러오는 중입니다." `role="status"`, 스켈레톤 행 `aria-hidden`, 실패는 표 안 `role="alert"` + 다시 시도 |
| 서버 정렬 링크(Tier 1) | Tab으로 이동해 Enter. 페이지를 새로 불러온 뒤 다음 Tab이 목록 안에서 시작한다(주소 끝 목록 제목 앵커) | `th[aria-sort]` 안의 링크, 링크 글자 뒤 숨김 글자로 동작("오름차순으로 정렬"), 아이콘 모양도 함께 바뀜 |
| 서버 페이지 링크(Tier 1) | Tab · Enter. 없는 이전 · 다음 쪽은 포커스되지 않는다 | `nav[aria-label]`, 쪽 번호 `aria-label="2페이지"`, 현재 쪽 `aria-current="page"`, 없는 이전 · 다음 `role="link" aria-disabled="true"`, 문서 제목에 쪽 번호 |
| 조회 조건 · 페이지 크기(GET 폼) | 고른 뒤 "검색" · "적용" 버튼으로 제출 | 선택만으로 페이지가 바뀌지 않는다(WCAG 3.2.2). 조회 조건 폼은 `role="search"` + 보이는 제목 |
| 상세 불러오기(`JejuDesign.load`) | 다시 시도는 Enter/Space. 버튼이 사라지면 포커스가 상태 영역으로 옮겨 간다 | 로딩·오류 상태와 같다. 다른 행을 빠르게 열면 마지막 요청의 결과만 보인다 |

## 10. 폼 상태 표현

폼 상태는 테두리 색 하나로 구분하지 않는다.

| 상태 | 시각 | 코드 |
|---|---|---|
| 기본 | 흰 배경 + 중립 테두리 | 없음 |
| hover | 테두리 강조 | 없음 |
| focus | `--jeju-focus-ring` | `:focus-visible` |
| readonly | `--jeju-readonly-bg` 배경 | `readonly` |
| disabled | `--jeju-disabled-bg` 배경 + 흐린 글자 | `disabled` |
| 필수 | 라벨 옆 “필수” 텍스트 | `required` |
| 오류 | 붉은 테두리 + 오류 문장 + 경고 아이콘 | `.is-error`, `aria-invalid="true"`, `aria-describedby` |
| 성공 | 초록 테두리 + 확인 문장 + 체크 아이콘 | `.is-success` |

제출 실패 시에는 폼 상단에 `.jeju-error-summary`를 두고 각 오류를 해당 입력으로 이동하는 링크로 제공한다.

오류·확인 문장은 `--jeju-feedback-font`(업무 12px · 대민 15px)를 쓴다. 대민 화면에서 오류 문장은 중요한 정보이므로 가장 작은 글자(13px)보다 한 단계 크게 둔다.

## 11. React 레지스트리(Tier 2) 구현

React 컴포넌트는 Radix 프리미티브가 9절의 키보드·ARIA 규약을 대부분 제공한다. 제주 레지스트리는 여기에 다음을 더했다.

- 포커스 표시는 Tier 1과 같은 `--jeju-focus-ring` 토큰을 쓴다. 토큰 파일을 `layer(base)`로 불러와도 전역 `:focus-visible` 규칙은 유지된다.
- 배경색으로만 상태가 드러나는 컨트롤(스위치, 체크박스, 라디오, 진행률, 현재 페이지, 눌린 칩·토글, 단계 표시)은 `forced-colors`에서 시스템 색(Highlight)으로 다시 그린다.
- 툴팁은 키보드 포커스로 열리고 Esc로 닫힌다. 마우스 클릭 직후처럼 키보드가 아닌 포커스에서는 열리지 않는다.
- 오류 요약(`ErrorSummary`)은 나타날 때 포커스를 받고, 각 항목은 해당 입력으로 포커스를 옮긴다. 입력에는 `aria-invalid`와 `aria-describedby`(오류 문장 id)를 함께 준다.
- 신청 마법사(`Wizard`)는 단계가 바뀌면 새 단계 영역으로 포커스를 옮기고, 진행 상황을 `aria-live` 문구로 알린다.
- 데이터 표의 선택 건수는 화면에 보이지 않는 `aria-live` 영역으로도 알린다. 행 체크박스 이름은 "관리번호 선택"처럼 행을 식별한다.
- 파일 업로드의 추가·삭제 결과와 용량 초과 안내도 문구로 알린다.
- 상세 패널(`DetailPanel`)은 표 안 버튼처럼 전용 Trigger 없이 상태로 열어도, 닫힐 때 연 요소로 포커스를 돌려준다.
- 로딩·오류 상태(`AsyncState`)와 서버 조회형 표는 다시 시도 버튼이 사라질 때 포커스를 상태 영역 · 건수 문구로 옮긴다.

## 12. 누를 수 있는 영역

| 프로필 | 기준 | 판정 |
|---|---|---|
| 업무 | WCAG 2.2 SC 2.5.8 Target Size (Minimum) | 24×24px 이상. 더 작으면 대상 중심의 지름 24px 원이 다른 대상이나 다른 작은 대상의 원과 겹치지 않아야 한다 |
| 대민 | KRDS 권장(캐러셀 가이드 "터치 조작 영역 최소 44×44px") | 실제로 누를 수 있는 영역(여백 포함) 자체가 44×44px 이상. 간격 예외를 쓰지 않는다 |

- 기준값은 `--jeju-target-min`이다(업무 24px · 대민 44px).
- 체크박스·라디오·스위치는 연결된 라벨까지 누를 수 있는 영역으로 본다. 그래서 선택 행(`.jeju-choice`, React 가로 배치 필드 라벨)의 최소 높이를 `--jeju-target-min`으로 둔다.
- 모양이 작아야 하는 아이콘 버튼(칩 제거)은 보이는 원을 작게 두고 `::after`로 누르는 영역만 넓힌다. 넓힌 영역이 다른 대상과 겹치지 않게 둔다.
- 문장 속 링크는 WCAG의 inline 예외에 해당한다. 경로 표시 · 메뉴 · 카드처럼 따로 떨어진 링크는 예외가 아니다.
- 브라우저 검증(`tools/e2e/verify-react.mjs`)이 예제 화면 전체를 390px · 1440px에서 이 기준으로 검사한다.

## 13. 인쇄

- 인쇄에서는 조작 요소가 빠지고 내용 · 조회 조건 · 출력 일시가 남는다. 인쇄물을 받는 사람도 어떤 조건의 목록인지 알 수 있어야 한다.
- 배경색은 인쇄 설정에 따라 빠진다. 상태 배지는 문구와 테두리로 남아 색 없이 읽힌다.
- 인쇄물에는 포커스 표시를 남기지 않는다. 화면의 `:focus-visible` 규칙은 그대로다.
- 대민 안내문은 외부 링크 뒤에 주소를 적어 종이에서도 찾아갈 수 있게 한다.
