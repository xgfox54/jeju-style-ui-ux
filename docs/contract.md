# 제주특별자치도 공통 디자인 계약

> **AUTHORITATIVE** — 제주 디자인 시스템 구현 규칙의 기준 문서.

## 1. 정본

디자인 값의 유일한 원천은 `design/jeju-tokens.css`다.

- 문서는 토큰 **이름과 역할**을 설명할 수 있다.
- HEX/RGB/spacing 값을 서비스 코드에 복제하여 새 기준을 만들지 않는다.
- 서비스는 가능하면 `var(--jeju-*)`를 직접 참조한다.
- `docs/tokens.md`(토큰 표)는 토큰 파일에서 만든 생성물이다. 직접 고치지 않고 `python tools/build_token_docs.py`로 다시 만든다(J19).

## 2. 브랜드

제주 포인트 원색은 다음 3축이다.

- Blue: `--jeju-blue`
- Green: `--jeju-green`
- Orange: `--jeju-orange`

세 원색의 값은 CI 근거 없이 변경하지 않는다.

Green/Orange 원색은 흰 글자와 일반 텍스트 AA 대비를 충족하지 않으므로, 채움 버튼·상태 텍스트에서는 `--jeju-green-dark`, `--jeju-orange-dark` 등 접근성 역할 토큰을 사용한다. 이 파생색은 원색을 대체하는 새로운 CI 색상이 아니라 **상호작용/텍스트 역할색**이다.

## 3. 프로필

### 업무(work)

기본값이다. 별도 속성이 없다.

- 한 화면에서 많은 정보를 처리하는 고밀도 레이아웃
- 표·검색·필터·폼·결재/처리 액션 중심
- 과도한 히어로, 마케팅 카피, 장식 애니메이션을 사용하지 않는다.

### 대민(public)

`<html data-jeju-profile="public">`로 활성화한다.

- 컨트롤 기본 높이 48px
- 본문 기본 글자 크기 17px
- 충분한 터치 타깃과 간격
- 누를 수 있는 요소는 실제로 누를 수 있는 영역이 44×44px 이상(KRDS 권장, `--jeju-target-min`)
- 가장 작은 글자는 13px(KRDS xsmall, `--jeju-text-xs`)
- 대민 헤더/푸터/기관 식별 영역
- KRDS 접근성·공공서비스 패턴을 참고

대민 프로필은 **색상·상태 의미를 재정의하지 않고 치수와 타이포 밀도만 변경**한다.

## 4. 접근성

- KWCAG/WCAG AA를 기본 목표로 한다.
- 일반 텍스트는 4.5:1 이상, 큰 텍스트 및 비텍스트 UI는 해당 기준을 따른다.
- 색만으로 상태를 전달하지 않는다.
- placeholder를 유일한 라벨로 사용하지 않는다.
- 모든 핵심 동작은 키보드로 도달 가능해야 한다.
- 누를 수 있는 대상은 업무 24×24px(WCAG 2.2 SC 2.5.8, 간격 예외 허용), 대민 44×44px 이상이다.
- `:focus-visible` 가시 포커스를 유지한다.
- Windows 고대비(`forced-colors`)에서 포커스와 상태 경계가 사라지지 않아야 한다.
- `prefers-reduced-motion`을 존중한다.

## 5. 컴포넌트

공통 컴포넌트는 `.jeju-*` 네임스페이스를 쓴다.

P0:
- 업무 셸(GNB/LNB/Main)
- 버튼
- 카드
- KPI
- 표
- 폼
- 배지/태그
- 알림
- 탭
- 페이지네이션
- 모달
- 빈 상태 · 로딩 · 오류 상태
- 대민 셸

서비스별 스타일은 공통 CSS **뒤에** 로드하고, 공통 컴포넌트의 의미를 깨는 전역 override를 피한다.

## 6. 네트워크/망분리

- 외부 폰트 CDN을 정본으로 사용하지 않는다.
- 필수 UI가 외부 JS/CSS가 끊겼을 때 붕괴하면 안 된다.
- 공통 동작은 dependency-free JS를 기본으로 제공한다.
- 글꼴은 자체 호스팅한다. `@font-face`는 `design/fonts/jeju-fonts.css`에 두고, 같은 폴더의 파일만 참조하며 외부 주소를 쓰지 않는다. `font-display: swap`으로 글꼴을 받는 동안에도 글자가 보이게 한다(J18).
- 글꼴 파일은 라이선스(SIL OFL 1.1) 확인과 기관 반입 승인 뒤 둔다. 파일이 없는 서비스는 토큰의 대체 글꼴로 표시되고 검사기가 WARN(S8)을 낸다. 외부 글꼴 주소는 FAIL이다.
- 망분리 기관에 화면을 전달할 때는 `tools/build_standalone.py`로 만든 단일 HTML을 쓴다. 외부 요청 없이 같은 화면과 동작이 나와야 한다(J17).
- React 레지스트리(Tier 2)는 npm 패키지가 아니라 정적 JSON 파일이며 내부 정적 서버로 서빙한다. Tier 2의 동작은 Radix 프리미티브를 쓰되, 설치된 소스는 서비스 저장소 안에 복사되어 외부 런타임에 의존하지 않는다.

## 7. AI 생성 코드

Codex/Claude 등 AI가 만드는 UI도 같은 계약을 따른다.

- 임의 HEX 추가 금지
- 임의 spacing 추가보다 토큰 우선
- 이모지로 핵심 UI 아이콘을 대체하지 않기
- 업무/대민 프로필 혼합 금지
- 빈 상태·오류·로딩 상태를 함께 설계하고 공통 상태 컴포넌트(`.jeju-state` · `data-jeju-async`, React `AsyncState`)를 쓴다
- 목록에서 한 건의 상세를 볼 때는 새 화면이나 임의 팝업 대신 사이드 패널(`.jeju-modal--side`, React `DetailPanel`)을 쓴다
- 적용 후 `python design/check_design.py --gate <서비스경로>` 실행

## 8. 변경 관리

브랜드 원색, 상태 의미, 프로필 경계, P0 컴포넌트 API 변경은 breaking change로 취급한다.

## 9. React 레지스트리(Tier 2)

- React · Next.js · Vite 서비스는 `@jeju` shadcn 레지스트리로 컴포넌트를 설치한다. 절차는 `docs/react-registry.md`다.
- 토큰 사본(`styles/jeju-tokens.css`)은 정본과 같아야 한다. 사본을 고치지 않고 정본을 고친 뒤 다시 설치한다.
- shadcn 테마 변수는 `var(--jeju-*)`로만 연결한다. 다크 팔레트를 만들지 않는다.
- 레지스트리 컴포넌트의 치수는 프로필 토큰을 따른다. 대민 프로필은 Tier 1과 같게 `data-jeju-profile="public"` 하나로 적용한다.
- Button · Badge · Alert의 변형 이름과 의미는 Tier 1 클래스와 같게 유지한다.
- 글꼴 선언은 `@jeju/jeju-fonts`로 설치하고 글꼴 파일은 `public/fonts/`에 둔다. 외부 글꼴 CDN을 링크하지 않는다.

## 10. 서버 조회형 목록

- 서버(JSP 등)가 정렬 · 페이지를 처리하는 목록은 조회 조건 · 정렬 · 페이지 · 페이지 크기를 주소의 조회 조건으로 주고받는다. 주소만으로 같은 화면을 다시 열 수 있어야 한다.
- 정렬은 `th[aria-sort]` 안의 `a.jeju-table__sort` 링크, 페이지 이동은 `nav.jeju-pagination` 안의 링크로 만든다. 현재 정렬 · 현재 쪽은 `aria-sort` · `aria-current`와 모양으로 함께 알린다.
- 선택 상자를 고르기만 해도 페이지가 바뀌게 하지 않는다. 페이지 크기 · 조회 조건은 "적용" · "검색" 버튼으로 제출한다.
- 링크와 폼 주소 끝에 목록 제목 앵커를 붙여, 새로 그린 뒤 키보드 위치가 목록에서 시작하게 한다.
- 목록 행을 다시 그려도 공통 훅이 동작해야 한다. 상세는 사이드 패널에서 `JejuDesign.load`로 불러온다.

## 11. 인쇄

- 인쇄물에는 조작 요소(메뉴 · 버튼 · 검색 폼 · 페이지 이동 · 선택 상자)가 남지 않는다. 대신 기관 · 조회 조건 · 출력 일시를 남긴다(`.jeju-print-header`, `data-jeju-print-date`).
- 표는 인쇄에서 가로 스크롤 없이 끝까지 펼친다. 머리글 행은 쪽마다 반복한다.
- 배경색이 빠져도 상태를 읽을 수 있어야 한다. 상태 배지는 문구와 테두리로 남는다.
- 상세 패널이 열려 있으면 패널 내용만 인쇄한다. 서비스 전용 인쇄 규칙은 공통 CSS 뒤에 두고 `.jeju-no-print` · `.jeju-print-only`를 먼저 쓴다.
